# 开发与发布

普通用户按[使用手册](使用手册.md)安装；本页供维护者。生产依赖由 `uv.lock` 和 `runtime-requirements.txt` 锁定，前端由 pnpm 锁文件锁定。使用 Windows x64 或 macOS 14+、便携 Python 3.12.14、Node 24、uv 0.12.10，以及 `plugin/package.json` 中的 pnpm 版本。

## 环境、测试和构建

```powershell
uv sync --managed-python --python 3.12.14 --extra dev --locked
$env:ZLB_DATA_DIR = Join-Path $pwd 'output/dev-test-state'
uv run pytest -q
cd plugin
corepack pnpm install --frozen-lockfile
corepack pnpm run check
corepack pnpm test
cd ..
uv run python scripts/build_runtime.py --repository Makashibata02/zotero-local-bilingual
cd plugin
corepack pnpm run build
cd ..
uv run python scripts/package_release.py --repository Makashibata02/zotero-local-bilingual
uv run python scripts/verify_release.py
```

必须先设置隔离的 `ZLB_DATA_DIR` 再导入应用，避免开发测试创建正式任务数据。普通测试只使用本地模拟 API，不需要真实 Key。免费联网验收是单独的主动操作，不属于默认测试。

引擎 ZIP、XPI、引擎清单、更新清单、源码 ZIP 和校验表只生成到 `dist/release-1.1.1/`，此目录不入库。服务变化需重建引擎；前端变化需重新构建 XPI。`--skip-dependencies` 仅适用于已有且核验过的同锁文件生产环境。`--repository` 留空生成纯离线候选地址。

公开 Release 支持匿名在线下载；插件明确不携带浏览器认证信息，也不持有 GitHub Token。离线 ZIP 入口常显，与在线选项共用校验和安装流程。发布说明使用中文，只描述更新内容；测试与审计记录单独存放。

## 数据与接口

XHTML／TypeScript → 回环 FastAPI → 独立 BabelDOC 工作进程 → SQLite 任务与费用审计 → PDF 产物。任务目录、缓存和凭据不随源码或发布包分发。

确认、上传入队和监控分离。全局并行 1 或 2，免费最多 1；同一 API 配置跨进程共享限流。任务锁防止服务异常退出时旧进程与恢复进程处理同一任务。旧未完成任务升级后暂停，预算不清零。

- `/v1/capabilities`：七语言与免费服务验收状态。
- GET／POST `/v1/scheduler`：全局并行上限。
- `/v1/jobs`：提交与列表，支持分页、搜索、状态及隐藏历史。
- POST `/v1/jobs/{id}/history`：隐藏／恢复；正式文件保留。
- 测试结果打开临时副本后 `cleanup-test`：仅清理明确标记的测试任务。
- POST `/v1/profiles/{id}/default`：独立默认 API；`initialize_only` 首次迁移优先采用当前配置，后续不覆盖默认。
- DELETE `/v1/profiles/{id}`：任务占用保护、凭据删除及配置墓碑；列表包含 `is_default`、`can_delete`、`delete_block_reason`。已删除配置不能通过旧保存请求复活，历史引用保留。
- `/v1/profiles/{id}/test`：一次连接调用；`selftest` 仅用于首次部署。

协议版本保持 2。任务含语言、书目信息和多产物，旧单产物入口保留。一次生成译文，再制作 dual／mono；缓存含源语言、目标语言和规则版本。日语 ja-JP、韩语 ko-KR 选择字体。免费适配器走传统翻译路径，API 模式走受保护的 LLM 接口。

资源只读，缓存另存。导入 BabelDOC 前设置缓存位置；运行时缺资源拒绝额外下载。独立进程隐藏启动、可单项取消；十分钟空闲退出，GET 轮询不延长空闲。

## 显式验收工具

- `scripts/acceptance_mock_api.py`、`acceptance_030.py`：便携引擎＋本地模型夹具，覆盖预算恢复、多语言、三产物和并行，不调用用户付费服务。
- `scripts/acceptance_languages_030.py`：主动免费联网验收，更新逐服务能力记录；更新后应检查差异并重建引擎。
- `scripts/acceptance_runtime.py --paper PUBLIC_SAMPLE.pdf --lecture LECTURE_SAMPLE.pdf`：外部 PDF 必须由调用者显式传入，无旧工作区依赖。未传入时只跑内置样本。
- `scripts/render_030_review.py --results PATH --pdf OUTPUT.pdf`：渲染显式提供的验收结果，不能替代源文核对。

浏览器模拟界面检查不等于 Zotero 原生交互。当前界面采用选项卡片、六列紧凑工作台及窄窗口任务卡片，已移除旧拖动列宽布局。

## 上传与分发

`scripts/repository_files.py` 提供统一源码白名单，供 Git 初次提交和源码包使用。排除开发依赖、研究副本、profile、Key、任务、日志、数据库和 PDF。上传前对工作树、首次 Git 历史、解包发布物运行 Gitleaks，报告隐藏秘密值；不能以 private 代替扫描。

Actions 仅手动触发构建，不自动创建 Release、Pages 或改变仓库可见性。维护者核对产物后将大文件放入 Release，不提交至 Git 历史。许可和原始 dist-info 许可证、字体清单随引擎保留。

复用已核验的生产引擎构建补丁版：`python scripts/build_runtime.py --reuse-engine dist/release-1.0.0/zlb-engine-1.0.0-windows-x64.zip --repository Makashibata02/zotero-local-bilingual`。校验旧 ZIP 的 SHA-256，保留锁定依赖和资源，只更新服务源码、许可清单及运行时版本；不访问用户运行目录或下载版面资源。

POST `/v1/runtime/shutdown-if-idle`：本机鉴权、预期版本及 PID 核对；托管后台在无任务和其他业务请求时进入退出状态，拒绝后续写入，CLI 完成优雅退出后插件才启动匹配引擎。健康接口提供 PID、退出能力、排队与业务请求状态。旧服务不支持此接口时不自动杀进程。


## macOS 与三平台构建

共享 XPI 从 `engine-manifest.json` 的 `engines` 中按 Zotero 进程架构选择 `windows-x64`、`macos-arm64` 或 `macos-x64`。Mac 安装目录含架构后缀；Rosetta 下的 Intel Zotero 会选择 x64 引擎。解压后仅固定的 `python/bin/python3.12` 设置执行权限；不创建符号链接，不移除隔离属性，不关闭 Gatekeeper。数据目录 0700、令牌 0600；服务和任务均使用 POSIX 文件锁。

Mac 钥匙串由 keyring 的 macOS 后端直接访问，无明文回退。拒绝保存会返回明确错误且不保存新配置；拒绝删除不会将配置标为已删除。生产 Key 不参与构建和测试。

维护者可在 Windows 上交叉组装 Mac 候选包，不能因此声称 Mac 原生运行通过。示例（先安装 uv，并把输出目录换成实际构建目录）：

```sh
uv python install cpython-3.12.14-macos-aarch64-none --install-dir output/python-downloads --no-bin --no-registry
python scripts/build_macos_runtime.py --platform macos-arm64 --python-home output/python-downloads/cpython-3.12.14-macos-aarch64-none --assets-from dist/release-1.0.2/zlb-engine-1.0.2-windows-x64.zip
```

Intel 将架构替换为 `x86_64`、平台替换为 `macos-x64`。资源源 ZIP 仅提供按清单校验的字体、模型等不可变资源，不复制 Windows 依赖。uv 安装仅允许有哈希的目标平台 wheel，不在用户机器执行安装。

Mac 原生构建调用相同脚本，使用该 Mac 的 uv 便携解释器；脚本会先运行资源加载和隔离后台启停检查，才设置 `native_verified=true`。交叉组装始终为 false。之后运行：

```sh
python scripts/verify_macos_binaries.py --runtime output/runtime-build/1.1.1-macos-arm64
python scripts/collect_engines.py
cd plugin
pnpm check
pnpm test
pnpm build
cd ..
python scripts/package_release.py
python scripts/verify_release.py
```

`collect_engines.py` 默认要求三平台 ZIP 都存在且哈希匹配。CI 为手动 `workflow_dispatch`，分别在 Windows、macos-14（ARM64）、macos-15-intel 上构建，合并后仅上传 Actions 候选附件，不创建 Release。工作流尚未在本轮提交或执行。

Mac 条件锁定 ONNX Runtime 1.23.2；Intel Mac 的 cryptography 锁定 48.0.1，原因是较新锁定版本不提供 Intel Mac wheel。Windows 保持 1.30.0／50.0.1。更新依赖后需重新解析两种架构并执行原生验收。

依据：[uv 目标平台安装](https://docs.astral.sh/uv/reference/cli/)、[便携 Python](https://docs.astral.sh/python-build-standalone/distributions/)、[keyring macOS 后端](https://keyring.readthedocs.io/en/stable/)、[Mozilla 文件权限接口](https://firefox-source-docs.mozilla.org/dom/ioutils_migration.html)、[GitHub 原生 Mac runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)。
